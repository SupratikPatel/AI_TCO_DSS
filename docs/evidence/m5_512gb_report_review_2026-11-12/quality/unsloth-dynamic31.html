Infrastructure and benchmark issues and fixes

  1. LiveCodeBench: Many runs had a Time Limit Exceeded issue, and we found CPUs were too heavily utilized on our machines - we regraded with full CPU affinity, flipping 385 answers from wrong to right

  2. LiveCodeBench: Official harness's stdin.buffer mock returned the first line on every readline and captured stdout had no .buffer . We fixed it with faithful stdin / stdout replacements. 468 answers flipped from wrong to right.

  3. AIME / HMMT / MATH-500: math_verify timeouts use signal.alarm, which fails off the main thread; the threaded grader fell back to exact string match (\frac14 vs \frac{1}{4} wrong). We fixed it with no timeouts off the main thread. 8,520 answers flipped from wrong to right (HMMT26 4,196, MATH-500 2,949, HMMT25 1,375)

  4. MATH-500 / HMMT: exact forms math_verify cannot parse (matrix spacing, \displaystyle, trailing punctuation, thousands separators, a = b chains, inequality vs interval, column vector vs tuple). We fixed it with exact rewrites only, never approximations; 18 fixture tests. This flipped 309 (MATH-500 198, HMMT25 89, HMMT26 22) answers from wrong to right.

Why the reference solution fails here

qemu-alpine-ssh

the verifier's apt-get install curl returns 404 (Debian bullseye security packages superseded), so its test tooling cannot install

qemu-startup

same 404

mcmc-sampling-stan

the reference needs RcppParallel, which needs cmake; the image has no cmake, so rstan cannot be installed

protein-assembly

build-cython-ext

install-windows-3.11

the reference QEMU build is OOM-killed (the build runs one job per host core, 192, in a 4 GB container)
